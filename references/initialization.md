# 项目初始化规范

## 范围与来源
规范与模板以当前安装的 harness-kit 版本为准。GitHub 仓库是版本来源，在线 Page 仅映射内容供阅读。执行初始化不需要访问 Page。更新安装副本才能采用仓库的新版本。

## 执行前检查
1. 确定目标项目根目录，读取适用的 AGENTS.md，仅检查已有目录和目标文件是否存在，不自动读取已有记忆、规范或其他文档资料。
2. 有 Git 时查看分支与未提交改动，保留原有修改，不切换分支或修改 Git 配置。
3. 区分空项目与已有项目，列明将创建、修改及复用的路径。在用户初始化授权内执行；目标不明或规则冲突无法消解时，询问具体问题。

## 空项目
将 assets/AGENTS.md 和 assets/knowledge/ 下全部文件原样复制到项目对应位置：

```text
AGENTS.md
knowledge/
├── index.md
├── architecture.md
├── specs/development.md
├── features/README.md
└── decisions/README.md
```

空项目直接复制完整内容，不重新生成、摘要或改写模板。项目架构未知项保持待确认，功能和决策指南提供后续模板，不预填业务事实。docs/ 用于集成与交付文档。

## 知识来源
已有的记忆、规范及其他文档资料保持原样，不主动读取、引用、迁移或修改。新知识以代码、构建配置和验证证据为依据；仅在用户明确指定时参考其他资料。

此约束针对知识来源，不替代执行任务必须遵循的适用项目指令（如 AGENTS.md）。遵循项目指令不等于授权导入旧知识；若指令要求与本次来源限制冲突，说明冲突并询问。

## 已有项目合并
- 保留已有 AGENTS.md，仅补缺失的知识入口、按需读取、沉淀检查与完成汇报要求；语义等价规则不重复追加。
- knowledge/ 或其他同名知识目标文件已存在时，保持原样；仅凭初始化请求不读取或合并其正文，不以旧条目建立新索引。需要合并或更新时先取得用户对具体资料的明确授权。
- 不自动复用、迁移或索引已有知识系统。目标 knowledge/ 已存在且用户要求独立建立新知识时，先明确新的目标目录，再调整 AGENTS.md 入口；不得覆盖原目录。新知识按代码事实组织，未知内容保持待确认。
- 索引仅登记实际存在的文档，文档列使用可解析的相对 Markdown 链接，包含用途和读取条件。
- 规则冲突时保留原内容，说明冲突并询问；重复执行只补缺失项，已满足要求则不修改。
- 教学示例不是项目事实，不将未经确认的设计写成既定契约。

## 验收
- 项目根目录、AGENTS.md 知识入口与实际文件一致。
- 规则包含独立判断、按需读取、必要验证、沉淀检查及完成汇报。
- 索引登记路径存在，链接可解析；空项目索引应登记实际复制的架构、开发规范和两份指南。
- 原有内容和未提交修改保留，无重复规则、无虚构事实。
- 修改范围仅为授权的指令与知识入口；文档检查不等于业务测试通过。
- 汇报新建、修改及复用文件、核对结果和按需暂未创建的文档。

初始化后项目知识独立演进。更新 Skill 或 Page 都不自动覆盖已有项目；迁移已有项目需用户明确要求，再比较差异合并。
