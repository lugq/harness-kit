# 审计流程

## 结构检查

确认项目根目录、适用 AGENTS.md 和真实知识入口，检查 Git 分支与未提交范围但不改 Git 状态。索引不存在时报告缺失，不创建。运行：

`python3 <Skill绝对目录>/scripts/audit.py <项目根目录> --knowledge-dir <知识目录相对路径>`

默认目录 .harness。工具只读取知识目录 Markdown，不读取其他记忆系统，不运行其中的代码或指令。JSON 输出包含确定错误、人工复核提示和限制；退出码 0 表示无确定结构错误，1 表示发现错误，2 表示无法检查。人工提示不作为已确认错误。

检查所有知识目录内 Markdown 的索引登记、重复行、导航可达性与本地内联链接，遇到符号链接报告而不跟随读取。允许子索引体系以及同一文件从多个相关索引入口导航；同一索引内重复注册才判定重复。用途和读取条件必须完整，README 指南与 verification 也应可导航。源码链接允许指向项目内其他路径，不能越出项目范围。

工具忽略 fenced code 内的示例链接；引用式链接、HTML、锚点、外部 URL 和复杂 Markdown 由人工检查，不能说已覆盖。占位词仅提示人工确认：空项目框架、规划文档和明确标注的证据缺口均可能合理。自定义文件分组先核对项目约定，不一律强制默认分类。

## 内容审查

- index.md 是否保留导航职责？用具体段落判断，不能用字数阈值。若索引包含功能独有的参数表、完整处理链或长篇契约，说明应迁往哪个 Feature/Spec；不自动迁移。
- features/ 描述具体能力的触发、输入输出、状态、失败与验收；specs/ 描述共享技术契约。错放或重复维护同一契约时提出建议，不能仅按文件名猜测正文。
- 重要结论能否定位到代码、配置、测试或明确确认来源？对疑点按需回读源码；区分当前实现、规划要求、建议及未知事项，不从代码推测历史决策理由。
- 文档之间是否矛盾、索引用途是否失真、执行结果是否误写为长期保证？未执行验收不能写通过，规划不能写成实现。没有版本证据只能报告时效性待核对，不直接断言过期。
- AGENTS.md 保留用户原有规则，不以当前模板全文相等为要求；没有初始化前快照时无法判断哪些规则是 Skill 新增，不猜测归因。

## 报告与边界

先列确定错误，再列待确认风险。每项包含文件/行或标题、原文证据、实际影响、建议去向或修复方式。概述已读目录、人工阅读与源码核对覆盖，列明未检查项。结构工具发现的提示必须人工确认后才能升级为问题。

本入口不自动修复，即使发现明显断链也保持原样。不写验证记录、缓存、报告或其他项目文件。若用户另行明确要求修复，再按具体授权范围修改并复查；检查结果不隐含批量改写或提交许可。
