# Harness 初始化

执行前读取 [初始化规范](references/initialization.md)。有代码时再读取 [从代码到可执行 Spec](references/source-to-spec.md)，按代码地图、主题划分、证据清单、写作与质量检查完成闭环。内置 assets 是结构参考，不是有代码项目的成品。先调查真实代码、构建配置与测试，再生成架构、技术约束、实际功能 Spec 和索引；只有真正无代码的项目才复制基础框架。不得把初始化等同于模板复制，也不得把本可查明的事实整篇留为待确认。

规范、模板随 GitHub 仓库版本分发，执行时使用当前安装版本，无需读取在线 Page。Page 只是阅读映射，不是运行时依赖或覆盖本地版本的来源。

先确定目标项目根目录并读取适用项目指令，仅检查已有文件的位置及未提交修改，不将已有知识资料自动作为来源；按初始化规范列明路径后执行。目标知识目录已存在时默认只盘点路径、不读取正文或写入；用户明确选择补缺失、更新、另建目录或迁移后，按授权范围执行。独立输出与是否修改 AGENTS.md 入口分别确定，保留人工内容，不复制教学示例。无法确定目标或明确规则冲突时就具体问题询问。

已有的记忆、规范及其他文档资料保持原样，不主动读取、引用、迁移或修改。新知识以代码、构建配置和验证证据为依据；仅在用户明确指定时参考其他资料。此约束针对知识来源，不替代必须遵循的适用项目指令（如 AGENTS.md）。同名目标文件的内容检查与合并边界见初始化规范。

初始化项目指令与基于代码事实的知识文档，不生成业务代码、不安装依赖、不创建其他 Skill，不自动提交、推送或部署。完成后核对文件、链接和修改范围，报告新建、修改及复用项。

## 写作模板

AGENTS.md 的新建与新增内容严格使用 [内置规则模板](assets/AGENTS.md)，不适用 Feature/Spec 的自由组织方式。无文件时逐字生成；已有文件时保留原文，仅逐字补入缺失的模板标题和规则，语义等价规则跳过。唯一允许替换项是用户已确定的知识目录路径。不得追加本次执行边界、旧资料位置、调查结果或自行发挥的规则。操作与校验方法见初始化规范的“AGENTS.md 严格模板规则”。

生成功能文档前读取 [Feature 模板](templates/feature.md)，生成技术契约前读取 [Spec 模板](templates/spec.md)。模板规定适用核心内容，不要求机械保留全部标题；按实际证据填充，不将模板说明直接写入完成文档。模板不属于 assets，不能作为项目成品直接复制。
