# 功能文档指南

按独立功能命名，小写英文与连字符，例如 image-processing.md，不加 feature- 前缀。日常修改优先更新对应文件，不按每次任务另建文档。

功能文档应说明范围、公开入口、从输入到输出的完整流程、数据与状态、失败/取消/释放，以及验收场景。跨页面或跨模块的数据需要核对两端，记录字段、类型、默认值、转换和调用位置。

关键结论就近链接真实代码与符号，区分当前实现、已确认契约和风险。共同技术规则链接 specs/，不重复复制。未确认事项写明具体证据缺口。

本次检查命令与执行结果集中到 [验证记录](../verification.md)；文档仅保留必要验证边界。创建文档后在 [索引](../index.md) 登记链接、用途与读取条件。

HarnessKit 初始化时使用 Skill 内 templates/feature.md 的完整写作骨架；它只约定结构，项目事实必须来自真实代码。
