# 从代码到可执行 Spec

本流程用于有代码项目；与 initialization.md 的来源限制和已有文件保护一起执行。方法参考 Trellis Spec Bootstrap 的先分析、再分解、再写作和验收思路；不依赖 Trellis、GitNexus、ABCoder 或特定平台，不读取旧知识来替代源码调查。

## 1. 建立代码地图

先查看源码目录、包清单、构建脚本、工作区配置、依赖与测试入口，形成模块清单。对每个主要模块标明职责、公开入口、依赖方向、代表性实现和测试位置。

从 App 入口或对外 API 追踪核心执行流：输入如何进入、如何验证、状态由谁保存、异常如何返回、资源由谁释放。跨模块任务要查看调用方与实现方，不能只看一个类或函数。

优先使用语言工具或已有代码检索能力定位符号；可用的图或 AST 工具只辅助导航，最终回读实际源码。没有工具时直接检索读取，不为初始化安装分析工具。排除构建产物、第三方实现、旧记忆及未经授权文档，避免递归读取整库文档。

## 2. 按真实边界划分主题

先列候选主题与证据，再决定输出文件。主题独立被开发者查询时拆分，重复内容多时合并。按包或运行层组织仅在项目确有这些边界时采用，不能强制套前端、后端或 Android 分类。

- architecture.md：真实模块与依赖全貌。
- specs/：多个功能需要遵循的本地实现模式与技术契约。
- features/：具体能力的输入输出、状态、边界行为与验收。
- decisions/：只记录有明确确认依据的取舍；没有依据则不编造历史。

允许调整模板章节、增加或合并主题；不适用章节直接省略。有代码项目不要求保留所有模板文件，但保留初始化与知识导航所需入口。编写指南可保留为指南，不能冒充已调查的项目事实。

## 3. 维护证据清单

调查过程中用简短工作笔记记录“主题 → 源文件与符号 → 观察到的模式 → 验证方式或缺口”。不必把原始笔记全部写入项目，但必须将源码基准、调查覆盖表和本次验证记录写入 verification.md，字段见初始化规范。

重要结论必须有源码、配置或测试支持。规则源于重复模式时核对多个代表性实例；只有单个实现证据时描述该实现与适用范围，不推广为全局规范。冲突实现明确记录差异，不擅自选一个宣布为标准。

源码路径和符号是稳定依据；行号仅在确认后作为辅助。未执行的测试只能说明已有测试覆盖的意图，不能写成此次验证通过。

## 4. 编写能指导开发的内容

按文档类型读取 ../templates/feature.md 或 ../templates/spec.md；命名用小写英文与连字符，不重复目录类型前缀。

先为每个核心功能检查入口、输入校验、处理、输出/保存/通知、失败/取消及释放；不要把“读过主要类”当作完成闭环调查。跨页面和跨层传值生成两端对照表，含字段、类型、默认值、转换及发送/接收符号。

每个主题按需要包括：适用条件、本项目的具体做法、真实路径与符号、边界行为、已发现的错误模式以及可靠的验证方式。无需机械保留全部标题。

公共 API 或跨层契约必须写到足够具体：准确签名或字段、类型与默认值（可确认时）、调用顺序、线程或生命周期要求、失败返回与错误处理。只摘录能澄清契约的短代码，不复制大段源码。

反例须有真实代码、测试或明确推导的依据；推导出的风险标为风险，不虚构已发生的 Bug。验证命令必须来自真实构建和测试配置，写清环境限制，不猜测命令或声称未经执行的结果。

避免“注意错误处理”“保持代码整洁”等无法帮助下一次修改的泛泛表述。功能验收写前置条件、操作和可观察结果，并区分预期行为与此次执行证据。

本次执行命令与结果集中在 verification.md；稳定契约留在 Feature/Spec，必要运行限制就近保留。不要在各文档重复调查流水账。

## 5. 最终质量关卡

- 从功能清单到文档检查覆盖：特别核对输出、保存、通知、取消和释放是否漏写。
- 从文档反查源码：逐条核对重要结论的实际分支、调用两端和最终赋值；文件存在不等于结论成立。
- 共同规则先核对所有声称覆盖的路径，再做概括；发现例外则缩小范围或列出差异。
- 关键结论就近关联文件与符号，不用章节末的大串文件链接代替证据。
- 跨边界表涵盖所有纳入范围的实际路径；遗漏路径明确标出，不把部分映射叫完整协议。

- 对照代码地图检查主要模块和核心功能的覆盖情况，明确未覆盖范围。
- 逐项核对重要契约、路径、符号和示例；发现矛盾回到代码调查。
- 搜索 TODO、placeholder、待填写等模板痕迹；删除填空提示与空标题，不把生成模板当成文档完成。
- 确有证据缺口时放入“未确认事项”，写明具体问题、已查范围与缺少的证据；不要简单清空不确定性标记以伪装完整。
- 清理重复和不适用的章节；仅处理本次新生成文件，不借清理删除或重写受保护旧资料。
- 检查索引列出实际文件，链接可解析，主题划分一致。
- 汇报生成文件、调查覆盖范围、关键证据、实际执行的检查及未验证边界。
