# 项目初始化规范

## 范围与来源
规范与模板以当前安装的 harness-kit 版本为准。GitHub 仓库是版本来源，在线 Page 仅映射内容供阅读。执行初始化不需要访问 Page。更新安装副本才能采用仓库的新版本。

## 执行前检查
1. 确定目标项目根目录，读取适用的 AGENTS.md，仅检查已有目录和目标文件是否存在，不自动读取已有记忆、规范或其他文档资料。
2. 有 Git 时查看分支与未提交改动，保留原有修改，不切换分支或修改 Git 配置。
3. 区分空项目与已有项目，列明将创建、修改及复用的路径。在用户初始化授权内执行；目标不明或规则冲突无法消解时，询问具体问题。

## 有代码项目的事实调查与文档生成

“尚无 .harness”不等于空项目。只要存在业务代码，就先调查后生成，不直接复制占位模板。

1. 列出源码模块、构建文件、依赖配置、测试和运行入口，排除生成产物、第三方源码及旧知识目录。遵守知识来源限制，不读取未获授权的旧文档。
2. 从公开接口或应用入口追踪主要调用链，确认模块职责、依赖、状态所有者、线程与资源生命周期。检查相关测试能证明哪些行为。
3. 按模块逐步阅读，覆盖一方源码的主要模块与可识别的核心功能；不以少量入口文件代表整个项目。大型仓库说明覆盖范围，未调查部分具体列出，不宣称全量完成。
4. 使用内置模板组织真实内容：architecture.md 写实际平台、模块路径、调用关系与边界；specs/ 写有代码或测试依据的技术约束；features/ 为实际识别的核心功能生成独立 Spec，包含触发条件、正常与异常行为、状态及公开入口。
5. 每项关键结论附真实源码文件与类、方法或配置项。区分当前实现、用户已确认契约和建议；不能把代码中的偶然实现提升为强制规范，不能从实现反推历史设计理由。
6. 建立可观察的验收场景并标明是否实际执行。选用与文档结论相关的可行验证；不为写文档安装依赖或修改业务代码。无法运行时说明限制，静态分析不等于行为验证。
7. index.md 登记所有实际生成的文档、用途与读取条件。features/README.md、decisions/README.md 保留编写指南；无已确认设计依据时不创建虚构决策记录。

可查明事实主动查明，待确认只保留确实缺少证据的问题，并说明缺少什么。已有目标资料的保护规则仍优先适用，不能借代码调查覆盖未授权文件。

## 真正无代码的项目

确认没有业务源码后，复制 assets/AGENTS.md 和 assets/.harness/ 下完整基础框架。架构项明确标为待确认，不编造模块、功能和决策。框架不代表已完成代码调查；汇报无代码状态。

## 输出结构

```text
AGENTS.md
.harness/
├── index.md
├── architecture.md
├── specs/development.md
├── specs/<实际技术主题>.md
├── features/README.md
├── features/<实际功能>.md
└── decisions/README.md
```

尖括号路径表示有证据后生成的实际文件，不创建字面占位文件。docs/ 用于集成与交付文档。

## 知识来源
已有的记忆、规范及其他文档资料保持原样，不主动读取、引用、迁移或修改。新知识以代码、构建配置和验证证据为依据；仅在用户明确指定时参考其他资料。

此约束针对知识来源，不替代执行任务必须遵循的适用项目指令（如 AGENTS.md）。遵循项目指令不等于授权导入旧知识；若指令要求与本次来源限制冲突，说明冲突并询问。

## 已有项目合并
- 保留已有 AGENTS.md，仅补缺失的知识入口、按需读取、沉淀检查与完成汇报要求；语义等价规则不重复追加。
- .harness/ 或其他同名知识目标文件已存在时，保持原样；仅凭初始化请求不读取或合并其正文，不以旧条目建立新索引。需要合并或更新时先取得用户对具体资料的明确授权。
- 不自动复用、迁移或索引已有知识系统。目标 .harness/ 已存在且用户要求独立建立新知识时，先明确新的目标目录，再调整 AGENTS.md 入口；不得覆盖原目录。新知识按代码事实组织，未知内容保持待确认。
- 索引仅登记实际存在的文档，文档列使用可解析的相对 Markdown 链接，包含用途和读取条件。
- 规则冲突时保留原内容，说明冲突并询问；重复执行只补缺失项，已满足要求则不修改。
- 教学示例不是项目事实，不将未经确认的设计写成既定契约。

## 验收
- 项目根目录、AGENTS.md 知识入口与实际文件一致。
- 规则包含独立判断、按需读取、必要验证、沉淀检查及完成汇报。
- 索引登记路径存在，链接可解析；索引登记实际生成或复制的文件，不链接未创建的主题。
- 原有内容和未提交修改保留，无重复规则、无虚构事实。
- 修改范围仅为授权的指令与知识入口；文档检查不等于业务测试通过。
- 有代码项目不能交付整篇待确认的架构占位文档；主要模块和核心功能有实际内容及源码依据。
- 汇报调查覆盖范围、生成文件、代码依据、实际验证及未解决事项；无代码项目明确说明仅建立框架。

初始化后项目知识独立演进。更新 Skill 或 Page 都不自动覆盖已有项目；迁移已有项目需用户明确要求，再比较差异合并。

## 目录版本变更
新项目默认使用 .harness/。已有 knowledge/ 或其他知识目录保持原样，不自动读取、迁移或修改；迁移必须由用户明确要求。.harness/ 是项目共享知识，应随项目提交 Git，不因点号目录而自动加入忽略规则。
