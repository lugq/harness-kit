# 项目初始化规范

## 范围与来源
规范与模板以当前安装的 harness-kit 版本为准。GitHub 仓库是版本来源，在线 Page 仅映射内容供阅读。执行初始化不需要访问 Page。更新安装副本才能采用仓库的新版本。

## 执行前检查
1. 确定目标项目根目录，读取适用的 AGENTS.md，仅检查已有目录和目标文件是否存在，不自动读取已有记忆、规范或其他文档资料。
2. 有 Git 时查看分支与未提交改动，保留原有修改，不切换分支或修改 Git 配置。
3. 区分空项目与已有项目，列明将创建、修改及复用的路径。在用户初始化授权内执行；目标不明或规则冲突无法消解时，询问具体问题。

## 有代码项目的事实调查与文档生成

详细分析与写作流程见 [source-to-spec.md](source-to-spec.md)。知识文档模板可根据实际代码边界增删章节、拆分或合并主题；不以固定文件数量作为完成标准。此灵活性不适用于 AGENTS.md。

“尚无 .harness”不等于空项目。只要存在业务代码，就先调查后生成，不直接复制占位模板。

1. 列出源码模块、构建文件、依赖配置、测试和运行入口，排除生成产物、第三方源码及旧知识目录。遵守知识来源限制，不读取未获授权的旧文档。
2. 从公开接口或应用入口追踪主要调用链，确认模块职责、依赖、状态所有者、线程与资源生命周期。检查相关测试能证明哪些行为。
3. 按模块逐步阅读，覆盖一方源码的主要模块与可识别的核心功能；不以少量入口文件代表整个项目。大型仓库说明覆盖范围，未调查部分具体列出，不宣称全量完成。
4. 使用内置模板组织真实内容：architecture.md 写实际平台、模块路径、调用关系与边界；specs/ 写有代码或测试依据的技术约束；features/ 为实际识别的核心功能生成独立 Spec，包含触发条件、正常与异常行为、状态及公开入口。
5. 每项关键结论附真实源码文件与类、方法或配置项。区分当前实现、用户已确认契约和建议；不能把代码中的偶然实现提升为强制规范，不能从实现反推历史设计理由。
6. 建立可观察的验收场景并标明是否实际执行。选用与文档结论相关的可行验证；不为写文档安装依赖或修改业务代码。无法运行时说明限制，静态分析不等于行为验证。
7. index.md 登记所有实际生成的文档、用途与读取条件。features/README.md、decisions/README.md 保留编写指南；无已确认设计依据时不创建虚构决策记录。

可查明事实主动查明，待确认只保留确实缺少证据的问题，并说明缺少什么。已有目标资料的保护规则仍优先适用，不能借代码调查覆盖未授权文件。

## 真正无代码的项目

确认没有业务源码后，按下方严格模板规则处理 AGENTS.md，复制 assets/.harness/ 下完整基础框架。架构项明确标为待确认，不编造模块、功能和决策。框架不代表已完成代码调查；汇报无代码状态。

## AGENTS.md 严格模板规则

新文件顶层标题固定为 `# Agent Guide`。“项目协作规则”使用二级标题，其内部小节使用三级标题。用两条独立 HTML 注释 `<!-- harness-kit:project-rules:start -->` 与 `<!-- harness-kit:project-rules:end -->` 标记模板规则区域；规则正文放在两条注释之间，不能包在同一条多行注释中隐藏。

已有文件保持原顶层标题与内容，不强制改成 Agent Guide。缺失模板规则只补入上述标记区域；若已有标记则在原区域内补缺失项，不再追加第二组标记。原规则语义等价时仍跳过；标记不赋予覆盖、删除或自动更新旧内容的权限。

无论项目是否有代码，新增规则的唯一文本来源都是 Skill 内 assets/AGENTS.md。先读取模板；仅允许将其中 `.harness/index.md` 的目录替换为用户已确定的项目相对知识目录，不能改写标题、措辞、标点或添加额外规则。

- 不存在 AGENTS.md：使用完整模板原文，只允许上述路径替换。
- 已有 AGENTS.md：先在临时工作目录保存原文件快照，保持原内容、换行及未提交修改不变。仅补缺失的模板规则，新增标题也必须取自模板；已有语义等价规则跳过，不为匹配模板改写原规则。可在对应已有章节补入或按模板分组追加，不重复顶层标题。
- 已有规则冲突时保留原文，报告冲突；不能自行创造折中规则。用户要求保留原入口或不修改 AGENTS.md 时，整个文件保持字节不变，不因本规范追加内容。
- 本次不读取旧资料、已有记忆目录位置、初始化过程、调查结果与验证日志均不进入 AGENTS.md；执行边界写入完成汇报，项目事实写入授权生成的知识文档。

生成后执行 `python3 <Skill绝对目录>/scripts/validate_agents.py <生成文件> --original <原文件快照>`；原本不存在文件时省略 --original。使用自定义知识目录时增加 `--knowledge-dir <项目相对目录>`。此检查仅验证新文本来自模板及原文本未删改；还须人工核对语义去重、规则冲突与是否获准修改入口。校验失败先修正文档，不能绕过检查交付。

## 输出结构

```text
AGENTS.md
.harness/
├── index.md
├── verification.md
├── architecture.md
├── specs/development.md
├── specs/<实际技术主题>.md
├── features/README.md
├── features/<实际功能>.md
└── decisions/README.md
```

尖括号路径表示有证据后生成的实际文件，不创建字面占位文件。.harness/ 是本 Skill 默认输出；其他目录的职责由目标项目决定，保持不变。

## 知识来源
已有的记忆、规范及其他文档资料保持原样，不主动读取、引用、迁移或修改。新知识以代码、构建配置和验证证据为依据；仅在用户明确指定时参考其他资料。

此约束针对知识来源，不替代执行任务必须遵循的适用项目指令（如 AGENTS.md）。遵循项目指令不等于授权导入旧知识；若指令要求与本次来源限制冲突，说明冲突并询问。

## 已有项目合并
- 按上方严格模板规则处理 AGENTS.md；保留原文，仅补缺失模板规则，语义等价规则不重复追加。
- .harness/ 或其他同名知识目标文件已存在时，保持原样；仅凭初始化请求不读取或合并其正文，不以旧条目建立新索引。需要合并或更新时先取得用户对具体资料的明确授权。
- 不自动复用、迁移或索引已有知识系统。目标 .harness/ 已存在且用户要求独立建立新知识时，明确新的目标目录和是否接入 AGENTS.md；用户要求保留原入口时只生成文档，汇报尚未接入；不得覆盖原目录。新知识按代码事实组织，未知内容保持待确认。
- 索引仅登记实际存在的文档，文档列使用可解析的相对 Markdown 链接，包含用途和读取条件。
- 规则冲突时保留原内容，说明冲突并询问；目标目录存在时默认只盘点路径、不写入。用户明确选择补缺失时只新建不存在文件；更新或迁移需明确授权具体资料的读取与修改，不默默覆盖原文件。
- 教学示例不是项目事实，不将未经确认的设计写成既定契约。

## 调查记录与规则来源

有代码项目必须生成 verification.md，格式参考内置 assets/.harness/verification.md；记录源码提交、分支、调查日期、是否纳入未提交改动，无 Git 则明确说明。不复制敏感 diff。先从入口/API 枚举候选主题，最终保存模块/入口、对应文档、已查范围与遗漏原因的覆盖表。

验证记录包含命令、工作目录、环境、结果及证明范围；区分实际执行、缓存命中、无测试源和未执行原因。空项目保留框架并说明未调查。已有记录保持原样；只有获准更新才追加带日期的本次记录，不覆盖历史。

内置 development.md 是 HarnessKit 引入的默认协作约定，不是源码事实，不能覆盖适用项目指令。有代码项目的 specs 主要记录具体技术契约；若保留默认约定，显式标注来源并与事实分开。

## 验收
- 有代码时通过 source-to-spec.md 的最终质量关卡：真实证据、具体契约、无残留填空提示、索引一致、覆盖范围明确。
- 已授权接入时，项目根目录、AGENTS.md 知识入口与实际文件一致；用户选择独立输出并保留原入口时，不要求接入新目录，保留 AGENTS.md 并明确汇报新文档尚未接入。
- 获准生成或补充 AGENTS.md 时通过严格模板校验，仅核对“文档读取”和“文档更新”两段；不得为满足旧版章节要求另加协作规则。保留文件模式检查字节不变。
- 索引登记路径存在，链接可解析；索引登记实际生成或复制的文件，不链接未创建的主题。
- 原有内容和未提交修改保留，无重复规则、无虚构事实。
- 修改范围仅为授权的指令与知识入口；文档检查不等于业务测试通过。
- 有代码项目不能交付整篇待确认的架构占位文档；主要模块和核心功能有实际内容及源码依据。
- 汇报调查覆盖范围、生成文件、代码依据、实际验证及未解决事项；无代码项目明确说明仅建立框架。

初始化后项目知识独立演进。更新 Skill 或 Page 都不自动覆盖已有项目；迁移已有项目需用户明确要求，再比较差异合并。

## 目录版本变更
新项目默认使用 .harness/。已有 knowledge/ 或其他知识目录保持原样，不自动读取、迁移或修改；迁移必须由用户明确要求。.harness/ 是项目共享知识，应随项目提交 Git，不因点号目录而自动加入忽略规则。
