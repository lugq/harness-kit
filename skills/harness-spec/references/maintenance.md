# 增量文档维护流程

## 定位与保护

1. 确定项目根目录、分支和未提交修改，读取适用 AGENTS.md，定位实际知识入口；自定义知识目录沿用现有入口，不能另造默认 .harness。没有已初始化入口或索引时报告缺失，建议先初始化；不擅自初始化或切换入口。
2. 阅读索引和本次主题相关文档、源码、构建及测试。列明拟新增、更新与保持不变的路径。索引仅用于导航，旧结论仍需源码复核；其他记忆系统及无关文档不自动读取。保留本次修改前的快照用于范围核对，不覆盖用户未提交工作。
3. 从公开入口列出主题的输入、状态、输出/保存/通知、失败/取消和释放。跨层契约核对调用两端。检查已有主题是否覆盖本次需求，优先更新，避免同一功能按任务重复建文件。

## 写作与联动

按 templates/feature.md 或 templates/spec.md 组织具体内容，文件名小写英文与连字符，不加 feature-/spec- 前缀。关键结论就近附相对源码链接与符号。区分源码当前实现、已确认需求、建议和证据缺口，不从实现推测历史设计理由；文档与代码冲突时说明差异，不把旧文档直接视为事实。

对已实现功能按源码生成完整行为与验收场景。对用户明确要求规划的未实现功能，标记“规划中／未实现”，仅写已确认范围、要求和待执行验收；模板中实现专属章节省略或说明未实现，不制造代码依据，不把规划验收标为已通过。

- 新文件必须登记实际知识入口 index.md 的表格，包含相对 Markdown 链接、用途、读取条件。已有文件若用途或读取条件变化则更新原行，路径不变不追加重复行。
- 仅当仓库本来使用分层索引时同步对应子索引，不自动新建层级；顶层索引可经子索引导航到文档。
- 共享契约有变化才更新相关 Spec；职责或依赖边界变化才更新 architecture.md；有用户确认依据才记录 decisions/。关联使用链接，避免复制同一权威契约表。
- 不改 AGENTS.md，不增加一次性执行规则，不更改无关资料或业务代码。仅新增文档不构成自动提交授权。

## 验证与记录

读取相关测试和实际配置，选择不安装依赖、不改业务代码的可行验证；避免会影响外部系统的检查。未执行、缓存命中、无测试源和真实通过分别记录。规划内容仅能验证文档一致性，不能声称功能通过。

运行 `python3 <Skill绝对目录>/scripts/check_docs.py <项目根目录> --index <知识入口相对路径> --document <本次文档相对路径>`；多个变更文件可重复 --document，存在子索引时可重复 --index。索引须包含用途和读取条件列。工具检查本次文件在提供的索引中唯一登记及所选索引、本次文档的本地链接，不检查全库或外部 URL；人工补查锚点和代码语义。不能为通过检查而随意修复无关文件，发现历史坏链接时报告并明确是否影响本次任务。

将本次实际检查追加到知识目录 verification.md，保留历史；不存在时仅在当前授权知识目录新建。记录日期、源码提交/分支、是否含工作区改动、本次调查覆盖与未覆盖范围，以及命令、工作目录、环境、结果和证明边界。不整篇重置初始化覆盖表，不复制敏感 diff。新建该文件时也登记索引。

最终核对修改前后差异：范围只包含本次相关知识与索引、验证记录，AGENTS.md 与业务文件不变，原未提交内容保留。报告新增或更新、未受影响的关联文档为何无需更新、实际验证和待确认问题。无新增长期知识时可不写文件，解释原因。
