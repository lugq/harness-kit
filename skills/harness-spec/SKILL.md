# Harness 文档维护

用于已初始化项目的增量维护。执行前读取 [维护流程](references/maintenance.md)，按需读取 [Feature 模板](templates/feature.md) 或 [Spec 模板](templates/spec.md)。模板随本 Skill 分发，不依赖其他 Skill 或在线 Page。

先确定项目根目录、适用项目指令、知识入口和本次主题。读取索引、直接相关的现有知识与源码，优先更新已有主题；不得借维护扫描、迁移或改写其他知识系统。用户请求维护某主题即授权读取该主题相关项目知识，不等于授权读取所有旧资料。

新增文档登记索引中的路径、用途、读取条件，修改已有条目不重复注册。仅在本次证据确实影响共享技术契约、架构或已确认决策时更新对应文档，不为齐全而修改所有文件。保持人工内容和未提交修改，不改 AGENTS.md、不写业务代码、不安装依赖、不自动提交或推送。

已有实现从真实入口追踪输入、处理、输出、失败和释放，关键结论附源码与符号。尚未实现的功能，仅在用户明确要求规划时记录已确认需求与验收，醒目标注“规划中／未实现”，省略不存在的代码契约和虚构路径。无法判断用户要开发还是写文档时先澄清，不把功能实现悄悄扩大为本 Skill 职责。

完成前运行本 Skill 的 scripts/check_docs.py 校验本次文档在索引中唯一登记、路径与相对链接有效；再人工核对代码事实、语义去重与影响范围。实际执行检查时按维护流程追加验证记录，未执行不能写成通过。汇报新建/更新文件、证据、验证和未确认事项。
