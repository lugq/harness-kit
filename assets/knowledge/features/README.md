# 功能文档指南

每个独立功能使用简短英文小写连字符文件名，如 feature-name.md。修改已有功能时优先更新对应文档，不按每次任务新建文件。

只记录已确认需求、真实行为和约束；未确认项单独列出，未执行的验收标为待验证。

## 功能 Spec 模板

```markdown
# 功能名称

状态：待确认
## 范围
目标、使用者、包含与不包含的行为。
## 功能契约
触发条件、输入输出、正常与异常行为。
## 状态与边界
状态来源、默认值、恢复与重置、生命周期、跨模块限制。
## 公开入口与代码依据
真实类、方法、接口及文件路径；区分预期契约和当前实现。
## 验收条件
使用可观察的场景描述前置条件、操作和预期结果。
## 验证记录
日期、环境、执行场景、结果与未覆盖项；尚未执行时写待验证。
## 关联与待确认事项
相关 Spec、架构、决策链接，以及待解决问题。
```

创建文档后在 ../index.md 登记相对链接、用途与读取条件。保留稳定知识，不复制调试流水账。
